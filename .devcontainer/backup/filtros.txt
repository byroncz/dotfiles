# Filtros de rclone para el respaldo del WORKSPACE (el código del proyecto).
#
# Sintaxis: "- patrón" excluye, "+ patrón" incluye. Se evalúan en orden y
# gana la primera que coincide, así que las inclusiones van ANTES.
#
# Criterio: se excluye lo que se regenera con un comando (dependencias,
# artefactos de build, cachés) y se conserva todo lo demás. Esas carpetas
# son además las que más archivos tienen, así que excluirlas es la
# diferencia entre un respaldo de segundos y uno de minutos.

# ── .git NO se excluye ─────────────────────────────────────────────────────
# Es justo lo que hace útil este respaldo. Ahí viven los commits que aún no
# has pusheado y los stashes: lo único del workspace que no existe en
# ningún otro sitio. Si excluyeras .git/, respaldarías solo la copia de
# trabajo y perderías precisamente lo irrecuperable.
+ .git/**

- node_modules/**
- .venv/**
- venv/**

- .bundle/**

- target/**
- dist/**

- __pycache__/**

# ── Worktrees de git (preparado, NO activo) ────────────────────────────────
# Un agente por worktree multiplica el respaldo: N worktrees son N copias
# completas del código, y `rclone sync` las sube todas.
#
# Estas reglas están listas pero COMENTADAS a propósito, porque activarlas
# tiene un coste que hay que aceptar a conciencia: un worktree contiene
# cambios sin commitear que no existen en ningún otro sitio, exactamente lo
# mismo que hace que .git sí se respalde. Excluirlo entero los pierde.
#
# Lo que NO hace falta activar: las carpetas regenerables de dentro de un
# worktree (node_modules, dist, __pycache__...) ya están cubiertas, porque
# las reglas de arriba no van ancladas y rclone las aplica a cualquier
# profundidad. Lo único que duplica un worktree es el código en sí.
#
# Descoméntalas cuando el número de worktrees haga que el respaldo tarde más
# de lo aceptable, y ajusta la ruta a la que uses de verdad:
# - .worktrees/**
# - worktrees/**
